# 迎角平台亏损 —— 合成阻尼、cos 投影与舵指令上限的三级分解

**日期**：2026-08-26　**弹种**：su_r_77_1（su_r_77 同构）　**场景**：A7 平射
（8 km / 方位 30° / 6300 m / 直线目标 / `ideal_truth`）
**数据**：`data/replays/r77_1_level_20260824.tsv`（46 帧游戏服务器回放读数）
**结论一句话**：模型迎角平台比游戏低 5.3°，其中 **2.2° 来自一个手填的临界阻尼
常数（是真实气动阻尼的 788 倍）**，2.1° 来自我们主动只打 89.8% 舵行程，
1.0° 来自制导投影漏了归一化。三项修完平台落在 23.5°，游戏 23.5–23.7°。

## 2. 数学模型

### 2.1 转弯链条

这个 plant（`plant_semantics = "fin_torque_body_aoa"`）不让舵直接产生转弯力。
链条分两步：

```
舵偏 δ  →  力矩把弹体绕质心拧  →  弹轴与气流成夹角 α  →  弹体产生横向力  →  弹道弯曲
```

横向过载几乎全部来自第二步（弹体在迎角下的"打包升力"），舵本身的力只占
`fin_translation_share` 的一小部分。所以**迎角才是过载的来源**，舵只是把
迎角"拧"出来的手段。

### 2.2 plant 方程

代码实现的是规格 §5 的二阶风向标模型：

```
I·ω̇ = K_M·(δ − α) − C·ω
```

按单位惯量写开（`h2_dynamics.py` 里就是这个形式）：

```
ω̇ = ω_n²·(δ − α) − 2ζ·ω_n·ω
```

其中刚度项

```
                scheduled_fins_g · g · Δ                    q
ω_n² = K = ─────────────────────────────── ,   scheduled_fins_g = A · ── · s
                 (L²/12) · δ_max                                       q₀
```

| 符号 | 含义 | 值 | 出处 |
|---|---|---|---|
| `A` | `finsLatAccel` 舵横向加速度能力 | 53.5864 g | **datamine** `rocket.finsLatAccel` |
| `Δ` | 质心到稳定面力臂 `distFromCmToStab` | 0.175 m | **datamine** `rocket.distFromCmToStab` |
| `δ_max` | 舵行程上限 `finsAoa` | 0.460812 rad = 26.40° | **datamine** `rocket.finsAoaHor/Ver` |
| `L` | 弹长 | 3.71 m | datamine |
| `I/m` | 转动惯量 | `L²/12` = 1.1470 m² | **假设**（匀质细杆） |
| `s` | 力矩斜率标度 `packed_lift_slope_scale` | 0.58 | **力通道拟合值，力矩通道无独立数据、直接沿用** |
| `q₀` | `baseIndSpeed` = 1800 km/h 对应动压 | 153 125 Pa | datamine（`η = q/q₀` 上限 4） |
| `ζ` | 阻尼比 | **1.0** | **假设**（规格手填，见 §4） |

R-77-1 在 6300 m 平台段：η ≈ 0.46–0.69，**ω_n ≈ 6.8–8.4 rad/s**。

### 2.3 稳态转弯的配平

代码注释写的是 `this plant trims at α = δ`。**这句话只在 ω = 0 时成立。**

导弹在持续转弯时，弹轴必须跟着弯曲的弹道一起转，所以 ω 恒不为零
（平台段实测 15–18 °/s）。令 `ω̇ = 0`：

```
ω_n²·(δ − α) = 2ζ·ω_n·ω        ⟹        δ − α = 2ζ·ω / ω_n
```

**迎角永远比舵角小一截，小的量正比于转速。**

数值验证（A7 平台段，独立用 config 里的 `A, Δ, δ_max, L, η` 算 ω_n，
不读 plant 内部量）：

| t (s) | 舵实际 δ | 迎角 α | 实测 δ−α | 公式 2ζω/ω_n | ω (°/s) | ω_n |
|---|---|---|---|---|---|---|
| 1.2 | 22.54° | 18.11° | **4.42°** | **4.41°** | 15.07 | 6.83 |
| 1.5 | 22.52° | 18.17° | **4.35°** | **4.30°** | 15.70 | 7.30 |
| 1.9 | 22.51° | 18.23° | **4.29°** | **4.24°** | 16.78 | 7.91 |
| 2.2 | 22.51° | 18.26° | **4.25°** | **4.22°** | 17.64 | 8.36 |

全段吻合到 **0.03–0.05°**。机制确定，不是猜的。

### 2.4 为什么平台是"死平"的

亏损 `2ζω/ω_n` 在整个平台上几乎不变，导弹从 471 m/s 加速到 576 m/s 也不变。
原因是速度在分子分母上抵消了：

- 转速 `ω = a_n/V`，而横向加速度 `a_n ∝ q·α/m ∝ ρV²α`，所以 `ω ∝ ρVα`
- `ω_n ∝ √K ∝ √q ∝ √ρ·V`

```
        2ζ·ω        ρVα
亏损 = ─────── ∝ ───────── = √ρ · α        （与速度无关）
        ω_n        √ρ · V
```

所以 **亏损 / α ≈ 常数**（6300 m 上是 0.233），迎角恒等于舵角的 **0.811 倍**，
导弹一路加速也不变 —— 这就是平台平得像尺子画的原因。

数值验证：

- **速度不敏感**：发射速度 800 → 1600 km/h（动压 4 倍），平台 18.08° → 18.32°，只动了 0.24°
- **密度敏感**：高度 1000 → 12000 m，亏损/α 从 0.301 降到 0.188（方向与 √ρ 一致；
  不是干净的 √ρ，因为 η 与 Mach 也随高度移动）

### 2.5 单点尾舵 rate-incidence 阻尼有多大

弹体绕质心转动时，尾舵在质心后方 Δ 处会横向扫过，扫动速度 `ω·Δ`。这个横向
速度叠加到来流上，把舵处的局部气流角改变了 `ω·Δ/V`。代码把它算成
`pitch/yaw_tail_rate_incidence_rad`。等效于把风向标弹簧的输入从 `(δ−α)` 改成
`(δ−α−ωΔ/V)`，于是

```
阻尼项 = ω_n² · (ω·Δ/V)        令其 = 2ζ_aero·ω_n·ω        ⟹        ζ_aero = ω_n·Δ / (2V)
```

（`ω_n ∝ V`，所以 `ζ_aero` 与速度无关。）代入平台段的数：

| t (s) | ω_n | V (m/s) | **ζ_aero** | 代码里的 ζ | 倍数 |
|---|---|---|---|---|---|
| 1.2 | 6.83 | 471.0 | 0.00127 | 1.00 | **788×** |
| 1.6 | 7.45 | 513.7 | 0.00127 | 1.00 | 788× |
| 2.0 | 8.06 | 555.6 | 0.00127 | 1.00 | 787× |

**措辞必须收窄（2026-08-26 复审要求）。** 788× 精确的含义是：

> 代码中的合成阻尼 ≈ 当前**单个尾舵作用站位**的局部 rate-incidence 阻尼项的 788 倍。

它**不是**"完整导弹总 C_mq 的 788 倍"。完整的转动阻尼还应包含弹体、翼面、尾舵
各站位的**分布式**贡献

    M_q ~ −(ω/V)·∫ x² dN_α(x)

以及自动驾驶仪可能存在的 q 反馈。`ω·Δ/V` 只是其中一个站位的一项，本文和
`docs/alpha_plateau_deficit.pdf` 早先把它直接称作"真实气动阻尼"，是过度概括，
以此段为准。

不过方向性结论不变：把合成阻尼关掉、只留 `ζ_aero`，闭环立刻剧烈振荡
（迎角在 45° → 11° → 39° → 6° 之间来回甩，脱靶 165 m），所以游戏那边**也必然
有额外阻尼**，只是没有 ζ=1 这么大。

### 3.1 刚度与阻尼 —— `src/aim120_model/h2_dynamics.py:1073-1094`

### 3.3 cos α 投影 —— `src/aim120_model/guidance.py:770-776`

```python
fin_fraction_mag = clamp(
    alpha_full_rad * demand_ratio / pitch_fin_limit_rad, 0.0, 1.0
)
raw_fin_fraction = limit_unit_disk(
    dot(demand_hat, axes.up) * fin_fraction_mag,
    dot(demand_hat, axes.right) * fin_fraction_mag,
)
```

`demand_hat` 是**垂直于速度**的单位矢量。弹轴与速度夹角就是 α，若 `demand_hat`
落在该迎角平面内，则 `demand_hat · f̂ = sin α`，于是它在弹体横截面 `(up, right)`
上的投影长度是 **cos α** —— 投影没有归一化就直接乘幅值，指令被削掉 cos α。

实测：平台期 `pcc_routed_alpha_deg` 精确等于 `23.7 × cos α`（两位小数吻合）。

正确写法是先把投影归一化再乘幅值。这个写法是从 `timer_blend` 直接舵路径继承来
的；在那条路径上幅值只是一个启发式的舵行程分数，cos α 的损失被
`fin_error_ref_rad` 的标定吸收了，所以无害。**一旦幅值的物理含义变成"迎角的
度数"（PCC-α 的 a_n⁻¹ 反演），它就成了系统性偏置**，而且 α 越大偏得越多。

### 3.4 `capture_alpha_max_deg` 的实际语义

同一段代码里，`alpha_full_rad = 23.7°`，`pitch_fin_limit_rad = 26.40°`，
捕获平台期 `demand_ratio` 被 clip 到 1，于是

```
fin_fraction_mag = 23.7 / 26.40 = 0.898
```

**这是一个舵行程分数。程序从头到尾没有拿实现出来的 α 和 23.7 比较过一次。**
它现在的实际语义是"把舵打到机械行程的 89.8%"，不是迎角限幅。迎角限幅的语义
只在 `α = δ`（即 ω = 0）时才成立，而捕获转弯里 ω 恒不为零。

同一个 23.7 还兼了第二个差事：释放包络

```
a_env = 力通道斜率 · α_max + T·sin(α_max)/(m·g)        （h2_dynamics.capture_alpha_envelope_g）
```

释放判据是 `R_cap = |a_cap| / a_env` 下穿 1。于是 **同一个常数同时决定舵指令
幅度和释放时刻** —— 这是后面 §6 那个耦合的来源。

附带一个自洽性问题：`a_env` 算的是"α = 23.7° 时能拉多少 G"，而飞机实际只到
18.26°，所以模型用的释放包络比它自己真拉得出的过载大 **30%**
（t = 2.2 s：`pcc_envelope_g` = 23.47 g，实际 `trajectory_lateral_load_g`
= 18.08 g，比值 1.298 = 23.7/18.26）。

### 3.5 顺带确认：没有任何东西在钳迎角

`control.limit_angle_of_attack_enabled = False`（`maximum_body_angle_of_attack_deg`
= 30° 未启用），`dynamics.clamp_body_angle_of_attack` 直接 return。
**动力学层面迎角没有上限**，18.26° 是配平出来的，不是被按住的。

## 4. 三级分解（实验）

方法：把 `src/` 整个复制到 scratchpad，在**副本**上加两个开关
（`_exp_zeta` 缩放合成阻尼、`_exp_fix_projection` 归一化投影），仓库未修改。
两个开关的默认值复现现状。同一发 A7，取 t = 1.6–1.9 s。

| 步骤 | 舵实际 δ | **迎角 α** | δ − α | 增量 | 性质 |
|---|---|---|---|---|---|
| 现状 | 22.51° | **18.2°** | 4.3° | — | |
| ① 归一化投影 | 23.70° | 19.2° | 4.5° | **+1.0°** | 写错了的地方 |
| ② + 满舵指令（α_max 23.7 → 26.4） | 26.40° | 21.3° | 5.1° | **+2.1°** | **故意的**（89.8% 舵行程） |
| ③ + ζ 1.0 → 0.5 | 26.4° | **23.5°** | 2.9° | **+2.2°** | **plant 的假设常数** |
| 游戏 | ?（上限 26.40°） | **23.5–23.7°** | 2.7°（若满舵） | | |

**对上了，差 0.2°。**

ζ 扫描（均为满舵指令 + 投影已修）：

| ζ | 平台 α | 建立段峰值 | 释放 t |
|---|---|---|---|
| 1.00 | 21.3° | 21.4°（单调无过冲） | 1.96 s |
| 0.70 | 22.6° | 23.0° | 1.82 s |
| **0.50** | **23.5°** | 25.7° | 1.74 s |
| 0.35 | 24.5° | 29.1° | 1.66 s |
| 0.0013（纯气动） | 发散振荡 | 45° | — |
| 游戏 | 23.5–23.7° | 23.2°（有小过冲，见 §5） | 2.1–2.3 s |

**独立复核**（不跑闭环，直接在游戏自己的工作点上算）：取回放 t = 1.5 s 的
V = 461.7 m/s、G = 15.8 g，反算 ω = 19.19 °/s、ω_n = 6.70 rad/s（η 按 V² 折算），
ζ=1 会给出配平亏损 5.73°，即满舵只能到 20.67°。要落在游戏的 23.7° 需要

```
ζ = (26.40 − 23.7) / 5.73 = 2.70 / 5.73 = 0.472
```

平台四帧（1.5 / 1.6 / 1.9 / 2.1 s）分别给出
**0.472 / 0.473 / 0.515 / 0.638**（最后一帧已进入释放段，不算数）。
闭环扫描和开环反算独立指向同一个 **ζ ≈ 0.5**。

## 5. 独立旁证：回放里的振铃

ζ = 1 是临界阻尼，**定义上不过冲**，阶跃响应严格单调。ζ < 1 会冲过头再回落。

回放的迎角建立段：

```
19.4 (0.7 s) → 23.2 (0.9) → 21.7 (1.1) → 22.8 (1.3) → 23.7 (1.5) → 23.7 (1.6)
                  ↑冲过头      ↑回落        ↑爬回来
```

模型 ζ = 0.5 自己长出同样的形状：

```
25.6 (0.7) → 25.7 (0.8) → 23.2 (1.3) → 23.6 (1.7)
```

而模型 ζ = 1 是 `18.7 → 19.8 → 20.4 → 20.8 → 21.0 → 21.1 …` **严格单调，
物理上不可能产生那个 V 形**。

**保留意见**：游戏那个 V 形只有 3 帧、幅度 ±0.75°，不能排除是截图读数误差。
它是一条与闭环拟合**独立**的证据线，但强度是"提示"级别，不是"判据"级别。
要坐实需要一段更高帧率的迎角建立过程 —— 振荡周期直接给 ω_n（即 K），
过冲量直接给 ζ，两个未知数两个观测量，还能用那 2.7° 的配平亏损交叉验证。

## 6. 代价与未解决

三级都改完并不是干净的胜利，如实记录：

**(a) 释放时刻提前了 0.4 s，且在已识别区间内修不回来。**
现状 t = 2.22 s 释放（游戏 2.1–2.3，正好）；改完提前到 1.74 s。原因是弹转得更好，
航向误差 ε 关得更快，`R_cap` 更早跌破 1。沿 `tau_capture_s` 的已识别区间
[0.23, 0.42] s 向下扫（小 τ 释放更晚）最多拉回 1.80 s，且 τ ≤ 0.26 就丢拦截：

| τ_c | 释放 t | α@1.9 | α@2.1 | α@2.3 | 结果 |
|---|---|---|---|---|---|
| 0.30 | 1.74 | 22.6 | 14.0 | 7.0 | 近炸 10 m |
| 0.26 | 1.78 | 23.2 | 15.5 | 7.9 | **脱靶 23 m** |
| 0.23 | 1.80 | 23.5 | 16.7 | 8.9 | **脱靶 15 m** |
| 游戏 | 2.1–2.3 | 23.5 | 22.9 | 20.6 | 近炸 7.2–7.4 s |

平台高度对了，但平台**变短了**。这与另一份诊断（释放悬崖：模型 90%→50% 用
0.24 s，游戏用 0.95 s；游戏的释放是斜率 −7.79 °/s 的**直线**，线性拟合
R² = 0.977 优于指数的 0.953）是同一个耦合问题的两面 —— 弹转得越好，悬崖来得
越早越陡。**两件事必须一起解，不能只修平台。**

**(b) 离轴冻结带会挂。** 用真正的冻结场景（`su_r_77`，无 loft，6500 m，25 s，
`tests/test_rate_inner_fin_torque.py::test_off_axis_envelope_with_raw_pid_autopilot`）：

| 方位 | 现状 | 三级改完（ζ=0.5, τ=0.23） | 冻结断言 |
|---|---|---|---|
| 80° | 17.8 m，不引信 | **10.0 m，引信起爆** | `!= proximity_fuse` 且 `15 < d < 40` → **挂** |
| 90° | 18.6 m，不引信 | 23.5 m，不引信 | `!= proximity_fuse` → 通过 |

**(c) 过载会偏高，因为迎角亏损一直在替热速度买单。**
平台 G：改完 17.1–17.7 g，游戏 15.8–16.6 g，高 1.1–1.3 g。现在的 18.2° 之所以
G 看着准，纯粹是"迎角偏低 16%"和"动压偏高 25%"两个错误互相抵消。
这与 `scripts/plant_g_closure_audit.py` 的结论一致（plant 本身在游戏工作点上
|ΔG| ≤ 0.17 g，误差全在阻力线程）：**修迎角必然暴露速度误差。**

| `capture_alpha_max_deg` | 23.7° | **单次回放读数** | 实际语义是舵指令分数，非迎角限幅 |

**关键点**：游戏数据里根本没有"迎角上限"这类字段。唯一真实的 AoA 类量是舵行程
上限 `finsAoa`。所以"游戏有没有迎角限幅"这个问题，等价于"满舵配平能不能落在
23.7°"，也就等价于 **ζ 是多少**。

- 若 ζ ≈ 0.5：游戏没有迎角限幅，平台就是**满舵配平**，23.7° 可以**从 datamine
  的舵行程上限直接推出来**，从"标定常数"升级为"导出量"，还跨弹种可预测。
- 若 ζ 真是 1：游戏必须另有一条迎角限幅 —— 但 datamine 里找不到它。

**简并声明**：单靠配平亏损这一个观测量，只能约束 **ζ/√K** 这一个组合，
ζ 和 K 各自不可分（亏损大一倍，可能是 ζ 大一倍，也可能是 K 小到四分之一）。
必须有第二个独立观测量才能分开。

**因此这个量不应该叫 ζ。** 平台亏损直接识别的是转速滞后时间

    tau_q = 2ζ / ω_n ,     δ − α = tau_q · ω

诚实的 ROM 参数化是 `ω̇ = ω_n²(δ − α − tau_q·ω)`：平台亏损识别 tau_q，
高频振荡周期识别 ω_n，最后才由 `ζ = tau_q·ω_n/2` 导出。在拿到第二个独立瞬态
观测之前，配置项应该叫 `effective_turn_rate_lag_s`（或
`equivalent_rate_damping_time_s`），**不要把 `zeta = 0.5` 写成已辨识的物理阻尼比**。
本文其余部分沿用 ζ 只是为了和代码里的 `2.0 * ω_n` 对应。

## 10. 2026-08-26 外部复审：两个比 ζ 更优先的结构问题

复审方完整解压补充包、读了四组 CSV / 回放 / 代码摘录 / config，并独立跑了
`check_plant_identity.py`。复核结论与本文一致（力矩恒等式残差 6.24e-9 / 7.92e-9
rad/s²，`ζ_implied` 均值 1.004，dt 与作动器均被排除，捕获期 PID 无舵权）。

在此之上提出两个**优先级高于 ζ** 的结构缺陷。两条都已在实验副本上验证成立。

### 10.1 `capture_alpha_max_deg` 一参两用 ⇒ 包络是错的

同一个常数同时充当 (1) 直接舵指令幅值、(2) 可达过载包络
`a_env = a_n(capture_alpha_max_deg)`。三级修正把它从 23.7° 改成 26.4°，等于同时
声明"舵打满 26.4°"和"弹体能达到 26.4° 迎角"，但同一次仿真实际只有 α ≈ 23.5°：

| t | a_env（旧） | 实际 G | 比值 |
|---|---|---|---|
| 1.2 s | 17.32 g | 15.30 g | 1.13 |
| 1.5 s | 19.25 g | 17.08 g | 1.13 |
| 1.7 s | 20.60 g | 18.39 g | 1.12 |

`R_cap = a_cap / a_env` 的分母因此不是真正的可达包络，"制导想要多少"与"弹体
能给多少"被混在一起。

**修法（复审给出，已实现于实验副本）**：满舵**动态**配平是一个一维标量求根

    α* + (2ζ / (ω_n·V))·a_n(α*) = δ_max ,        a_n(α) = a_aero(α,q,M) + T·sin α / m

f(0) < 0、f(δ_max) > 0、单调，二分即可，无需调参。真正的包络是 `a_env = a_n(α*)`，
不是 `a_n(δ_max)`。实现为 `h2_dynamics.capture_trim_alpha_rad()`。
验证：修正后 t=1.5 s 的 `a_env = 17.25 g` vs 实际 `17.08 g`，误差从 13% 降到 1%。

语义也要拆开，不要再让一个键代表舵角、迎角和包络三件事：

    fin_deflection_limit_deg   = 26.4    # datamine，舵角
    capture_envelope_mode      = full_fin_trim
    capture_trim_alpha_deg     = 导出量，不是配置
    capture_alpha_limit_deg    = 仅用于"显式迎角限幅"假说

### 10.2 PCC 直接舵路径绕过了 datamine 的 launch gain —— 这才是释放提前的主因

datamine 的 `guidance.flight_time_gain_table`（来自 `timeToGain*`）是
`(0.30 s, 0) → (0.31 s, 1)`：**发射后前 0.30 s 自动驾驶仪增益为 0**。

代码算了它（`guidance.py:607-611`）：

    flight_gain = interpolate_table(time_s, guidance_cfg["flight_time_gain_table"])
    effective_gain = flight_gain * hit_gain
    pn = scale(pn_raw, effective_gain)

**但 `effective_gain` 只乘到了 `pn` 上。** `capture_accel_mag = V·sin ε / τ_c`
（line 707）和整条 direct-fin 路由完全没乘。所以 PCC 从 t=0 就以全权限打舵。

补充观察：这不是 PCC 专有的。`timer_blend` 路径的 `midcourse_accel` 同样没乘
`effective_gain`，`loft` 项也没有。**整条 midcourse 通道对全弹种都绕过了这个
datamine 增益表。**

ζ=1 的迟钝 plant 部分掩盖了它；ζ 改 0.5 之后早段过快立刻暴露：

| t | 游戏 α | baseline | 三级修正（无 G） |
|---|---|---|---|
| 0.7 s | 19.4° | 16.6° | **25.6°** |
| 0.9 s | 23.2° | 17.8° | **25.0°** |

累计航向 `J_ψ(0.9)`：三级修正 **10.64°**，baseline 7.02°，游戏重构 ≈ **4.7°**。

**零参数 ablation（G）** = 把已经算好的 `effective_gain` 也乘到捕获通道和直接舵
路由上。结果见 §10.3。

### 10.4 dt 分岔与一次性 latch

复审发现三级修正落在一个 hybrid threshold 分岔附近：交接后最大航向偏移在
dt=0.02 下达 15.46°、dt=0.002 下只有 13.14°，正好跨过 `epsilon_exit_deg = 15°`，
于是模式序列完全不同（4 次切换 vs 1 次）。复核确认：

|---|---|---|---|---|---|---|
| P+Fcmd+Fenv+Z（无 G/L） | 0.020 | 23.42 | 7.75 | 1.76 | 6 | 脱靶 30.3 m |
| 同上 | 0.010 | 23.42 | 6.94 | 1.76 | 4 | 脱靶 16.9 m |
| 同上 | 0.002 | 23.42 | 6.65 | 1.76 | **1** | 近炸 10.0 m |

### 10.5 冻结带 —— 更正：这条断言本身就是 dt=0.02 的假象

**上一版本文在此处写"全部+latch 留在带内"，那是只跑了 dt=0.02 的错误结论，
以本节为准。**

按复审要求把 80° 单独跑了 dt × τ_q × q∞ 敏感性，结果暴露的是**冻结带本身**的问题：

| 配置 | dt=0.020 | dt=0.010 | dt=0.002 |
|---|---|---|---|
| **出厂现状** | 17.8 m 不引信 ✅ | **11.4 m 不引信 ❌** | **10.0 m 引信起爆 ❌** |
| commit-2（P+Fenv+G+L） | 47.9 m 不引信 | 47.8 m 不引信 | 45.1 m 不引信 |
| commit-3（+Fcmd+τ_q） | 16.5 m 不引信 ✅ | 10.0 m 引信 ❌ | 10.0 m 引信 ❌ |

**出厂模型自己在收敛步长下就挂这条断言。** 原因是数值的，不是物理的：

`minimum_distance_m` 与近炸引信触发**都只在积分步上求值，没有最接近点插值**。
80° 弹道在最接近点附近的逐步距离读数是

    dt=0.020:  39.7 → 21.5 → 17.8 → 33.8 → 54.2 m     （每步跨 ~16 m 距离变化）
    dt=0.002:  12.7 → 11.1 → 10.0                      （分辨得出来，引信触发）

近炸半径 10 m，粗步长下导弹**一步跨过整个引信球**。所以
`!= proximity_fuse` 与 `15 < d < 40` 这两条冻结断言记录的是**采样漏检**，
不是模型行为。

后果：

1. 所有以 `minimum_distance_m` 为阈值的离轴冻结断言都是在一个 dt 相关量上标定的，
   需要重新审视；
2. 正确修法是给最接近点加插值（对 range(t) 做局部二次拟合求极小），
   使 `min_d` 与引信判定对 dt 不敏感 —— 这是独立于本文主线的一个数值缺陷；
3. 在那之前，**不能**用 80° 的名义值给任何改动背书。commit-2 集在三档 dt 上是
   收敛的（47.9/47.8/45.1，均不引信），commit-3 集不是（16.5/10.0/10.0）。

其余敏感性（dt=0.02 名义点，仅供参考，因为基准本身不可靠）：
τ_q ×0.95 → 14.0 m，×1.05 → 19.0 m；q∞ ×0.97 → 19.6 m，×1.03 → 13.8 m。
即 ±5% 的 τ_q 或 ±3% 的动压就能让名义值跨过 15 m 下界。

对照：代码当前 ζ=1 ⇒ τ_q = **0.291 s**；ζ=0.5 ⇒ τ_q = **0.146 s**。

读法：

- **s_K 跨 64 倍，τ_q 只从 0.166 变到 0.329 s（2 倍）**，而 SSE 在 s_K ≥ 4 之后
  完全平（0.698 → 0.689 → 0.688）。这就是复审说的简并，现在有量了：
  **τ_q 被约束，s_K（即 ω_n、即 ζ）不被约束。**
- 在"现有 K 公式不变"（s_K = 1）这一点上，τ_q = **0.212 s**，换算 ζ = **0.73**，
  **不是闭环扫描给的 0.5**。差别的来源是闭环扫描里 τ_q 还在替热速度买单
  （闭环 q 高 25% ⇒ ω_n 高 12%），而 replay-forced 把 q 强制成了游戏值。
  **所以 0.5 那个数不应该再被引用；R-77-1 的经验值应记为
  `effective_turn_rate_lag_s = 0.212`（在 s_K = 1 前提下）。**
- **高度确实不是阻塞项**：h = 6000/6300/6600 m 给 τ_q = 0.2106/0.2124/0.2142 s，
  ±1%。复审的预判成立。
- **`q_b(t0)` 在 s_K ≥ 0.5 时全部顶在 60 °/s 的界上。** 拟合想要一个比 datamine
  `rateMax` 还大的初始体角速度 —— 说明"前半拍偏慢"是**结构性**的，不是 τ_q 能修的。
  这与复审 §6 的判断一致，而且现在是在**去掉阻力线程之后**看到的，所以也不是热速度造成的。
