§ 1现象

回放里发射捕获段（"甩头"）的迎角被钉在一个平台上，而同期过载一直在爬—— 15.8 g 涨到 17.8 g。这个组合本身就是判据：如果饱和发生在过载通道，过载应该一起平掉。 过载通道的上限 reqAccelMax = loadFactorMax = 50 g，两个都是 datamine 值，远未触及。

模型跑同一发，平台只有 18.2°。舵的机械行程上限 26.40°（datamine rocket.finsAoaHor）明明还有余量。 问题是：这 5.3° 是我们故意限出来的，还是 plant 自己跑出来的？

答案是两个都有，而且可以精确拆开。

§ 3数学模型

转弯链条

这个 plant（plant_semantics = "fin_torque_body_aoa"）不让舵直接产生转弯力，链条分两步： 舵偏产生力矩把弹体绕质心拧，弹轴与气流成夹角 α，弹体在迎角下产生的横向力才是转弯的来源。 舵本身的力只占很小一部分。所以迎角是过载的来源，舵只是把迎角"拧"出来的手段。

稳态转弯的配平——"α = δ"只在不转弯时成立

代码注释写的是 this plant trims at α = δ。 这句话只在 ω = 0 时成立。 导弹持续转弯时，弹轴必须跟着弯曲的弹道一起转，ω 恒不为零（平台段实测 15–18 °/s）。令 ω̇ = 0：

ω_n²·(δ − α) = 2ζ·ω_n·ω ⟹ δ − α = 2ζ·ω / ω_n

迎角永远比舵角小一截，小的量正比于转速。逐点核对（ωn 独立用 config 算，不读 plant 内部量）：

为什么平台是"死平"的

亏损在整个平台上几乎不变，导弹从 471 m/s 加速到 576 m/s 也不变。原因是速度在分子分母上抵消了： 转速 ω = a_n/V 而 a_n ∝ ρV²α，所以 ω ∝ ρVα； 而 ω_n ∝ √q ∝ √ρ·V。

2ζ·ω ρVα 亏损 = ─────── ∝ ────────── = √ρ · α （与速度无关） ω_n √ρ · V

所以 亏损 / α ≈ 常数（6300 m 上是 0.233），迎角恒等于舵角的 0.811 倍—— 这就是平台平得像尺子画的原因。数值验证：发射速度 800 → 1600 km/h（动压 4 倍）， 平台只从 18.08° 动到 18.32°；高度 1000 → 12000 m，亏损/α 从 0.301 降到 0.188。

§ 4单点尾舵 rate-incidence 阻尼有多大

弹体绕质心转动时，尾舵在质心后方 Δ 处横向扫过，扫动速度 ω·Δ。 这个横向速度叠加到来流上，把舵处的局部气流角改变了 ω·Δ/V， 代码把它算成 tail_rate_incidence_rad。等效于把风向标弹簧的输入从 (δ−α) 改成 (δ−α−ωΔ/V)：

阻尼项 = ω_n²·(ω·Δ/V) 令其 = 2ζ_aero·ω_n·ω ⟹ ζ_aero = ω_n·Δ / (2V) （ω_n ∝ V，故与速度无关）

788× 精确的含义是：代码里的合成阻尼 ≈ 当前单个尾舵作用站位的局部 rate-incidence 项的 788 倍。它不是"完整导弹总 Cmq 的 788 倍"—— 完整转动阻尼还包含弹体、翼面、尾舵各站位的分布式贡献 （Mq ~ −(ω/V)·∫x²dNα(x)）以及自动驾驶仪可能的 q 反馈。

方向性结论不变：把合成阻尼关掉、只留 ζaero，闭环立刻剧烈振荡——迎角在 45° → 11° → 39° → 6° 之间来回甩，脱靶 165 m。所以游戏那边也必然有额外阻尼， 只是没有 ζ=1 这么大。

    alpha_full_rad * demand_ratio / pitch_fin_limit_rad, 0.0, 1.0)
raw_fin_fraction = limit_unit_disk(
    dot(demand_hat, axes.up)    * fin_fraction_mag,   # ← 投影未归一化

demand_hat 是垂直于速度的单位矢量。弹轴与速度夹角就是 α， 于是它在弹体横截面 (up, right) 上的投影长度是 cos α—— 投影没有归一化就直接乘幅值，指令被削掉 cos α。 实测平台期 pcc_routed_alpha_deg 精确等于 23.7 × cos α。

这个写法从 timer_blend 直接舵路径继承而来；在那条路径上幅值只是个启发式的舵行程分数， cos α 的损失被 fin_error_ref_rad 的标定吸收了，所以无害。 一旦幅值的物理含义变成"迎角的度数"，它就成了系统性偏置，而且 α 越大偏得越多。

capture_alpha_max_deg 的实际语义

同一段代码里 alpha_full_rad = 23.7°、pitch_fin_limit_rad = 26.40°， 捕获平台期 demand_ratio 被 clip 到 1，于是 fin_fraction_mag = 23.7/26.40 = 0.898。

这是一个舵行程分数。程序从头到尾没有拿实现出来的 α 和 23.7 比较过一次。 它现在的实际语义是"把舵打到机械行程的 89.8%"，不是迎角限幅——迎角限幅的语义只在 ω = 0 时才成立。 顺带确认：control.limit_angle_of_attack_enabled = False， 动力学层面没有任何东西在钳迎角，18.26° 是配平出来的。

§ 7独立旁证：回放里的振铃

ζ = 1 是临界阻尼，定义上不过冲，阶跃响应严格单调。ζ < 1 会冲过头再回落。 回放的迎角建立段： 

19.4 (0.7 s) → 23.2 (0.9) → 21.7 (1.1) → 22.8 (1.3) → 23.7 (1.5) → 23.7 (1.6)
                  ↑冲过头       ↑回落        ↑爬回来

模型 ζ = 0.5 自己长出同样的形状：25.6 (0.7) → 25.7 (0.8) → 23.2 (1.3) → 23.6 (1.7)。 而模型 ζ = 1 是 18.7 → 19.8 → 20.4 → 20.8 → 21.0 → 21.1， 严格单调，物理上不可能产生那个 V 形。

保留意见

游戏那个 V 形只有 3 帧、幅度 ±0.75°，不能排除是截图读数误差。 它是一条与闭环拟合独立的证据线，但强度是"提示"级别，不是"判据"级别。 要坐实需要一段更高帧率的迎角建立过程——振荡周期直接给 ωn，过冲量直接给 ζ。

§ 8为什么这件事同时决定"游戏有没有迎角限幅"

扫了全部 120 个弹种配置：游戏数据里根本没有"迎角上限"这类字段。 CyMaxAoA 非空 0/120，CyK 非空 0/120。 唯一真实的 AoA 类量是舵行程上限 finsAoa。

所以"游戏有没有迎角限幅"这个问题，等价于"满舵配平能不能落在 23.7°"，也就等价于 ζ 是多少：

  • 若 ζ ≈ 0.5：游戏没有迎角限幅，平台就是满舵配平， 23.7° 可以从 datamine 的舵行程上限直接推出来—— 从"标定常数"升级为"导出量"，还跨弹种可预测。
  • 若 ζ 真是 1：游戏必须另有一条迎角限幅——但 datamine 里找不到它。
简并声明 —— 而且这个量不该叫 ζ

单靠配平亏损这一个观测量，只能约束 ζ/√K 这一个组合，ζ 和 K 各自不可分 （亏损大一倍，可能是 ζ 大一倍，也可能是 K 小到四分之一）。必须有第二个独立观测量才能分开。

平台亏损直接识别的其实是转速滞后时间 τq = 2ζ/ωn，因为 δ − α = τq·ω。诚实的 ROM 参数化是 ω̇ = ω_n²(δ − α − τ_q·ω)：平台亏损识别 τq，高频振荡周期识别 ωn，最后才由 ζ = τqωn/2 导出。在拿到第二个独立瞬态观测之前， 配置项应该叫 effective_turn_rate_lag_s，不要把 zeta = 0.5 写成已辨识的物理阻尼比。

§ 9可证伪路径

按判别力排序：

  • 高帧率的迎角建立段（任意弹种、任意几何）。振荡周期 → ωn，过冲量 → ζ， 两者还必须同时复现配平亏损。这是唯一能解开上面那个简并的实验。 现有 46 帧不够：0.7–0.9 s 之间只有两个点。
  • 跨弹种平台。finsAoa 是 datamine 且弹间差 1.7 倍 （AIM-120 = 15.41°、PL-12 = 21.49°、R-77 = 26.40°、AIM-54 = 25.0°）。 满舵配平 ⇒ 各弹平台按各自 finsAoa 标度；固定迎角限幅 ⇒ 不跟着走。 现有数据不足——唯一有"钉住平台"的只有 R-77-1 这一发。需要一发 AIM-120 或 PL-12 的平射捕获回放。
  • 不同高度的平射。§3 预测亏损 ∝ √ρ，是一条纯几何、不含自由参数的标度律，可直接证伪。

§ 10外部复审：两个比 ζ 更优先的结构问题

复审方独立复核了力矩恒等式（残差 6.24e-9 / 7.92e-9 rad/s²）、ζimplied = 1.004、 dt 与作动器排除、捕获期 PID 无舵权，全部与上文一致。在此之上指出两个**优先级高于 ζ** 的缺陷。 两条都已在实验副本上复现并修好。

① capture_alpha_max_deg 一参两用 ⇒ 包络是错的

同一个常数既当直接舵指令幅值，又当可达过载包络 a_env = a_n(capture_alpha_max_deg)。 把它改成 26.4° 等于同时声明"舵打满 26.4°"和"弹体能到 26.4° 迎角"，但实际只有 α ≈ 23.5°： t=1.5 s 时 a_env = 19.25 g 而实际只有 17.08 g， R_cap 的分母根本不是可达包络。

正确做法是解满舵动态配平的一维标量方程：

α* + (2ζ / (ω_n·V))·a_n(α*) = δ_max f(0) < 0、f(δ_max) > 0、单调 ⇒ 二分即可，无需调参 a_env = a_n(α*) 而不是 a_n(δ_max)

修正后 t=1.5 s 的 a_env = 17.25 g vs 实际 17.08 g——误差从 13% 降到 1%。

② PCC 直接舵路径绕过了 datamine 的 launch gain

datamine 的 flight_time_gain_table（来自 timeToGain*）是 (0.30 s, 0) → (0.31 s, 1)：发射后前 0.30 s 自动驾驶仪增益为 0。 代码算了它，但 effective_gain 只乘到了 PN 上—— a_cap = V·sinε/τ_c 和整条 direct-fin 路由完全没乘。所以 PCC 从 t=0 就全权限打舵。

补充观察：这不是 PCC 专有的。timer_blend 的 midcourse_accel 和 loft 项同样没乘——整条 midcourse 通道对全弹种都绕过了这个增益表。

ζ=1 的迟钝 plant 掩盖了它；ζ 改 0.5 后早段过快立刻暴露：α@0.7 s 冲到 25.6°（游戏 19.4°）， 累计航向 Jψ(0.9) = 10.64°（游戏重构 ≈ 4.7°）。

冻结带这次没被打破

真正的冻结场景（su_r_77，无 loft，6500 m）：80° 从 17.8 m/43.6 g 变成 16.5 m/40.0 g，仍不引信——留在 15<d<40 且 25<maxG<50 带内；90° 29.6 m，仍不引信。 对比旧三级修正在 80° 会引信起爆（10.0 m）直接挂断言。

主线已经改变

现在最可能的主线不是"继续调 ζ"，而是"正确构造满舵动态配平包络 + 补上 PCC 绕过的 launch gain"。这两项之后再看平台高度、释放时刻和早段累计航向能否同时闭合。 下一步最干净的识别路径是 replay-forced plant run：把 V(t)/q(t)/m(t)/T(t) 强制成游戏时间线，只积分 α/ω/δ，在不受阻力误差与制导几何污染的条件下识别 τq、ωn、τact。
